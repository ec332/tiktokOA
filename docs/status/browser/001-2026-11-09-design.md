# P7 browser runner: design (2026-11-09)

Brief: `docs/iteration3/P7-browser-runner.md`. Settled by `docs/iteration3/rules.md` (U5), with no debate with the user. Serves FB-a, CR1, CR4, K4 (DR-1, DR-4). Hand-off brief read: W0 (`W0-contracts.md`), for C1, C3, C4, C5, C10 and C11, which P7 consumes. No other brief was read.

Everything below runs on the SYNTHETIC notify fixture (C10). Model calls in this component's tests are scripted fakes (K5). A real proposal by the model is I1's (CLAUDE.md §4), and so is the measurement for K4.

| # | Question | Brief said | Decided | Rule | Serves | Evidence |
|---|---|---|---|---|---|---|
| D1 | Propose flows at discover time, or on every run? | Recommend discover time, verified once per commit | **Discover time.** `ui_flows.run` proposes and verifies once per discovery (one discovery per commit). No model acts during a test run | R2, R4 | DR-1, CR1, CR4 | — |
| D2 | The flow IR | YAML steps `goto`, `fill`, `click`, `expect_request`, `read_back`; role and name locators only | `{name, steps}`. A step is a one-key map: `goto: <path>`; `fill: {role, name, value}`; `click: {role, name}`; `expect_request: {method, path, status}`; `read_back: {path, contains}`. Locators are `get_by_role(role, name=…, exact=True)`. `ui.parse()` rejects any other key, any CSS or XPath, and any unknown placeholder: a proposal is model output, so it is checked at the boundary | R1, R3 | FB-a, C5 | C5's `checks.value.ui` shape |
| D3 | Values a flow types | Not stated | A literal, or one of two placeholders: `$TP_SECRET_ADMIN_PASSWORD` (from the runner's env) and `$TP_UNIQUE` (`record.name("ui")`, new for each execution, so K runs on one database never collide). Nothing else from the env can be typed into a page. The record keeps the placeholder, never the value | R6, hard limits (secrets) | CR4, K5 | The runner gets `TP_SECRET_ADMIN_PASSWORD` exactly when `auth.login` exists (`tp/stages/env/blackbox.py:682-688`) |
| D4 | Who writes `expect_request` and `read_back` | "Accepted only if running it shows the create request, and an API read-back finds the typed value" | **A fixed rule, not the model.** The model proposes `goto`, `fill` and `click` only. Running them shows the create request: the 2xx POST, PUT or PATCH whose request body carries the typed `$TP_UNIQUE` value. It is matched to its spec operation. The read-back is the first parameterless spec GET (the create's own path first, at most 5 tried) whose answer contains the value, read by discovery through `d.http` (probe-recorded). Both are then appended to the flow as `expect_request` and `read_back`, and `verified` is `{op, read_back}` | R4 | DR-1, CR1 | — |
| D5 | What the model sees, and how often it is asked | "Reads Playwright's accessibility snapshot and proposes one flow: sign in, then create" | Playwright's `aria_snapshot()` of the page body. One proposal, then at most 2 repairs. A repair gets the error and the snapshot taken where the flow failed. A page error is never repaired: the page is broken, not the flow | R3, R6 | CR1, K4 | The fixture's note form is `hidden` until sign-in (`tests/fixtures/sut/notify/app.py:90`), so a first snapshot can't show it |
| D6 | Where the browser runs at discover time | Not stated | In the browser runner image, on the stack's run network (`d.stack.egress`), through `d.probes`, so a replay needs no Docker. `python -m platform_rt.ui snapshot` and `python -m platform_rt.ui run` (flow on stdin, JSON on stdout) call the same `execute()` as the pytest item: one code path for verifying and for running | R3 | DR-1, U1 | Discovery's probe rule (`tp/stages/discover/discovery.py:55-81`) |
| D7 | How a flow becomes a record | "Actions become exchange steps (`kind: ui`); network responses become HTTP exchanges" | A UI action is an exchange `{kind: "ui", method: "UI", path: 'click button "Save note"', status: 0, …}`. Each document, fetch or XHR response is an HTTP exchange of the usual shape. Keys that look sensitive (`platform_rt.standin.SENSITIVE`) are redacted in bodies. `expect_request`'s match is `under_test`, and its created resource goes to `$TP_LEDGER`, so the namespace clean-up deletes it | R3, R1 | C1, C3, CR2 | `classify` compares `status >= 500` on the last exchange (`platform_rt/platform_rt/origin.py:121-123`), so a UI step needs an integer status |
| D8 | Failures and origins | `pageerror` → `UiPageError`; locator timeout → `LocatorError` | As the brief. Page errors are checked before each step and at the end. A Playwright `TimeoutError` or strict-mode violation on a locator → `LocatorError` (BINDING). `goto` that can't connect → `httpx.ConnectError` (ENV). No create request seen, or a read-back miss → `ExpectationFailed` (ASSERTION) | R2 | C3, C7, CR4 | `origin.py:116-119` |
| D9 | Screenshots and waiting | Screenshot on failure only; Playwright's own retries 0 | A PNG next to `$TP_RESULTS` (`ui/<nonce>.png`), its path and the aria snapshot in `observed`, on failure only. No pytest-playwright and no retry wrapper. Actions auto-wait up to `TP_UI_TIMEOUT` (default 5 s). `goto` waits for `domcontentloaded`, never for page idle | R2 | CR4 | Memos never reaches page idle in headless Chromium (`docs/status/integration/001-2026-11-09-status.md` §5) |
| D10 | The provider | `checks.value.ui` → bound entries, the flow inlined and hashed | One entry per flow: `{unit: "U:<name>", ac: None, file: "<name>.ui.yaml", status: "BOUND", kind: "ui", generic: True, source: <yaml>, lock_hash: sha256(source)}`. None when a run is limited to some units, as for the families. Node id `<name>.ui.yaml::<name>[U:<name>]`; the gate makes `U:<name>` its criterion | R3 | C3, C4, DR-4 | `tp/stages/generate/stage.py:44-48`; `tp/stages/gate/stage.py:101-105` |
| D11 | The flow's name | Not stated | `create_<last segment of the create path>`, e.g. `create_notes`: a fixed rule from the run | R4 | — | — |
| D12 | The image | "Built from the runner image, plus Playwright and Chromium, pinned" | `images/runner-browser/Dockerfile`: `FROM ${BASE}` (the black-box runner) + `playwright==1.64.1` + `pyyaml==6.0.3` + `playwright install --with-deps --only-shell chromium`. Playwright 1.64.1 is the newest release older than two weeks (PyPI, checked 2026-11-09); each Playwright release pins its Chromium build | R2, R3 | SR3, FB-a | — |
| D13 | Who builds the image | `published_browser()` only, in `image.py` | `tp/stages/generate/ui.py:build_image(tag=None, base=None)` builds it (tagged by its inputs' hash, so an unchanged one is a cached no-op) and publishes `runner_browser`. `entries()` calls it when there are flows, and `ui_flows` before it proposes. `published_browser()` stays a reader | R7 | C4, C11 | P7 owns only `published_browser()` in `image.py` (master §3) |
| D14 | When discovery proposes no flow | Not stated | No model; external reach (a live system gets no writes, U1); no HTML page at `/`; no `auth.login` (so no password for the runner). Each skip is emitted with its reason | R1, hard limits | U1 | — |

Memos (I1). A second UI target. Playwright reproductions, a UI section in the report, traces and HARs (they hold tokens). Browser traffic through the safe-mode proxy on external targets (D14 skips external reach). Trace headers on browser requests.
