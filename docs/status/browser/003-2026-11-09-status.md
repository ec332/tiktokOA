## Found and fixed (within Owns)

**Chromium upgraded `http://app:8080` to HTTPS** (`net::ERR_SSL_PROTOCOL_ERROR`). A one-label host is read as a TLD, and `app` is an HSTS-preloaded TLD. The pipeline names a Dockerfile target's service `app` (`tp/stages/discover/discovery.py:359`), so every real run on such a target would have hit this. httpx to the same URL answered 200.

- Fix, `77ccfb9`: `platform_rt.ui.page_base()` gives the browser the service's IP when the host has one label. API calls (`read_back`, clean-up) keep `$TP_BASE_URL`.
- Limit (a `shortcut:` comment in the code): the page's Host header is then the IP. A target that checks Host needs a dotted alias mapped with `--host-resolver-rules`.
- Test, `7c2f1ac`: `test_a_one_label_host_is_reached_by_its_ip`.
