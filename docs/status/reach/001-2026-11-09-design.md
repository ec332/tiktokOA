# P2 reach and sandbox: design (2026-11-09)

Brief: `docs/iteration3/P2-reach-sandbox.md`. Agreed with the user on 2026-11-09 ("carry on with the suggested items and the lean implementations"). Serves CR2, CR3, FB-b, FB-c, U1, DR-9.

| # | Decision | The brief said | Agreed | Why |
|---|---|---|---|---|
| D1 | Compose environment (H1) | Minimal environment rather than escaping `$` | A minimal environment: `PATH`, `DOCKER_HOST`/`DOCKER_CONTEXT` when set, `DOCKER_CONFIG` (the real `~/.docker`), plus the run's values. **No `HOME`.** The allow-list lives in `config/sandbox.yaml` | Escaping breaks `${X:-default}`. With `HOME` passed, `${HOME}:/host-home` would still resolve (U1) |
| D2 | `$` in paths (H2) | Refuse `${` in volume sources and build contexts | Refuse any `$` in a volume source, a build context or a `dockerfile`. `env_file` paths and the `dockerfile` resolve (following symlinks) inside the checkout | `rewrite` already moves `./`, `/` and `~` sources under the env dir; a `$` source was the one that passed through |
| D3 | Build cache key | The sha plus the variant patch's hash | Reference `:<sha12>`; a variant `:<sha12>-<hash of its patch set, 8 chars>`. The patch hashes go into the fingerprint | A variant is a different build, and retest's env diff must see it (DR-10) |
| D4 | Dockerfile reach | Build the root Dockerfile, cached per commit | A generated one-service compose, `app` with `build: {context: ., dockerfile: Dockerfile}` and `expose: [<EXPOSE port>]`, fed through the existing `rewrite`. `reach.value.build = {dockerfile, context, port}` (C5). No `EXPOSE` gives a `setup` question | One code path: the internal network, forwarder, limits, cache and stand-ins all apply unchanged (K3) |
| D5 | Where a variant's patch goes | "Applies the variant's patch to the checkout, then builds" | **Changed:** `git archive HEAD` into the variant's env dir, patches applied there, then the build. The clone is never written. An image-only target refuses any variant (DR-9) | An interrupted in-place build leaves the clone dirty (the template needs `stray_patches` for this); scope 5 says never write into the checkout |
| D6 | Variant names | Not stated | The existing grammar. `bug:<seed>[+<seed>]` and `fixed:<patch>` resolve through `service.fix_patch`: the profile's `patches/` folder, or a `sha256:` artifact. Tests copy notify's seeds into the test profile's `patches/`; for b3, I1 adds a labelled patch to `targets/<slug>/patches/` | No new profile key, so C5 is unchanged |
| D7 | Compose projects | Not stated | One per variant: `tp_bb_<slug>` for the reference, plus `__<variant>` otherwise. The reference `Stack.variant(v)` returns a cached sibling; `Reach` and `Checks` route through it | Execute reads the reference logs after tearing a variant down (`execute/stage.py:94-96`); a shared project would have replaced them |
| D8 | Variables with no value | Copy `.env.example`/`.env.sample`, generate secret-like names, otherwise ask | Secret-like names (`platform.secret_name`), in any form: generated, kept in the slug's secret store, passed to compose as process env, never written to a file. `${X:?…}`/`${X?…}` and a missing `env_file` with no example: a `setup` question. **Bare `${X}`, any other name: empty, as compose does, recorded not asked.** The example is copied to the run dir as `.env`, which compose reads. Resolved at every bring-up, not only in discovery | A question for every optional knob would stop most compose files at setup. Every bring-up must resolve the same values, so a retest gets them too |
| D9 | The runner reaching stand-in journals (C8) | "Let the runner reach their journals" | **Adds to C8 (user OK 2026-11-09):** `families_config()` gains `standins: [{name, kind, url, journal}]`, so the runner's families read the addresses from `TP_FAMILIES`. Stand-ins are services `tp-standin-<name>` on the run network, and the app `depends_on` them | C8 gave the network path but no address. P6's families already read `TP_FAMILIES`. P6 must be told |
| D10 | Tests | Fixtures only | Compose fixtures under `tests/fixtures/compose/`: hostile (from `probe_sandbox.py`) and required-variable. Notify is copied into a tmp git repo (the cache key needs a sha), so there is no non-git path. Docker tests are marked `docker`, projects `it3-p2-*`, the stand-in stub is built from `python:3.14-slim` as `:p2-dev`. The no-internet check targets 203.0.113.1 (TEST-NET-3), so nothing real is contacted even if it leaks | U1, §4 of CLAUDE.md |
