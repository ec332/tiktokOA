# Baseline — design (M6 Impact)

Plan: Part 5, "Baseline comparison" row; Part 6 M6 ("three-arm table"). Agreed with the user on 2026-11-01 ("implement the recommendations leanly").

| # | Decision | Plan said | Agreed | Why |
|---|---|---|---|---|
| B1 | Fixed set | "same variants and mutants" | Variants: `reference`, each `bug:FLAG` alone, `fixed:fix-pagination`. Mutants: the gate's 134 (same mutmut generation, same runner digest; names checked). Strength denominator = all 134 for every arm | No arm can win on a smaller denominator |
| B2 | Detection | — | Arm-neutral flip rules, no triage. Seeded: passes all K on `reference`, fails all K on `bug:FLAG`. Real bug (O-6): fails all K on `reference`, passes all K on `fixed:fix-pagination`. Kill: the test's call phase fails under the mutant (junit `<failure>`, not `<error>`) | The other arms have no triage; counting it would favour the platform |
| B3 | Mutant off during setup | platform_rt does it per setup request (gate 002) | A pytest plugin (`tp/baseline/mutant_phase.py`, `-p mutant_phase`) blanks `MUTANT_UNDER_TEST` in setup/teardown for arms a/b | Otherwise a mutant in auth/crud breaks the session fixtures, everything errors in setup, and nothing can be a kill |
| B4 | Platform arm | — | Read from existing artifacts by id: seeded from `run_records dfb6c25a…` (x252, K=3), real bug from `retest 91080c4e…` (`fixed:fix-pagination`), mutants from `gate_report e06c537d…`. Image check: the current published runner digest and backend image id must match the fingerprint in `run_records aefea7ec…` (same `bound_tests`); otherwise re-run | Re-running repeats signed work; the check keeps it fair |
| B5 | What the naive LLM sees | "LLM sees code" | Upstream backend source at `f4bcfab` (git, without our patches) + the SUT test conftest and `tests/utils` helpers (fixtures only, not the tests). No requirements | The patched tree contains `settings.BUG_*`: it would leak the seeded bugs |
| B6 | Naive pipeline | "failing tests dropped or repaired" | Haiku 5.5, one call for ~60 in-process pytest tests on the SUT's fixtures; run on `reference`; ≤3 repair rounds (generate's budget) on failing tests; still failing → dropped | Same model and repair budget as the platform, so the gap is method, not budget |
| B7 | Naive samples | — | N=3 independent samples (option `--samples`) | The only stochastic, unreviewed arm |
| B8 | Metrics | seeded (authored/blind), real bug, mutation strength, share of bug-validating tests | Seeded authored = deterministic flags detected /3 (OWNERSHIP, TITLE_MAX, INACTIVE_LOGIN); race flag shown separately; blind = "— (M7)"; real bug yes/no; strength = kills/134; bug-validating share = tests that flip on ≥1 bug/fix pair ÷ tests kept; plus test count, cost, repaired/dropped | Plan metrics; blind bugs are M7 |
| B9 | Code shape | `tp/baseline/` | `python -m tp.baseline naive` (AI: `naive_tests` artifact, LLM recorded through the gateway) and `python -m tp.baseline compare` (deterministic: `baseline_report` artifact + `baseline.md` table). Not a pipeline stage: the CLI and runner only know the nine stages, and changing them is skeleton work | Lineage and labels without touching tp/core or tp/cli |
| B10 | Bias | — | Footnote: requirements, seeded bugs and platform tests share one author → authored-seeded favours the platform; blind (M7) exists for that | Honesty |

**In-process execution for arms a/b.** Through `ctx.env.pytest` (in_process, reference DB, the variant's flags as settings) with `TP_MODE=network` in the env, so the env harness's per-test rollback and leak guard stay off. The SUT's tests manage their own DB (commit, and delete everything at session end); the leak guard would fail them. `fixed:fix-pagination` is run in-process by overlaying the patched `items.py` (read-only mount, the same mechanism as mutants), because the runner image holds the reference code.

**Parked:** web panel, blind bugs, route-handler mutants (K8), triage-explained column for the other arms, registering baseline as a pipeline stage.
