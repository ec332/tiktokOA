## 4. The end-to-end flow

input → discover → spec → clarify → cases → sign-off → generate → gate → env → execute → triage → report → retest → deliver

| Stage | Proven on | Notes |
|---|---|---|
| Discover | Memos, Paperless, aspnetcore, express-bookshelf, the notify fixture | from a repo URL with no target code; each field carries its source, layer and probe evidence |
| Spec → cases → sign-off | the template (attended); Memos, RealWorld (unattended) | unattended criteria are labelled "assumed" |
| Generate → gate | pytest cases, generic families from the spec, `.ui.yaml` flows | K stable runs, a shuffled run, planted bugs |
| Env → execute | the template stack; black-box targets on an internal network with stand-ins; a live system through the proxy | sealed, write-once run folders |

- On black-box targets, localisation is at the API level, plus the handler file where the source exists.

- No factory for a second user: 9 of 55 RealWorld cases are unbound.
