## Fixes found by the real runs

1. **The black-box runner image vanished between builds.** generate now always calls `build_blackbox()`, which is tagged by the wheel's hash, so an unchanged wheel is a Docker-cached no-op (r-0010 failed here).
2. **The drafter invents precondition names** (`archivist`, `tag_exists`). Cases now moves non-factory preconditions into leading `Given: …` steps. When the target has exactly one principal, that principal is the caller unless the case is anonymous; the scaffold counts `admin` as a caller.
3. **Execute's sealed records bypassed artifact scrubbing.** `record.write` now redacts before sealing.
4. **The black-box env spec lacked `reproduce`**, which execute reads.
5. **Triage did `Path(None)`** for a target without source.
6. **The report printed `mutation strength 0/0`.** It now says "not measured" when the gate didn't measure.
7. **Read-back timeout, measured:** the Paperless upload → document read-back took 14–57 s over 9 runs. The 60 s guess (D8) was too tight, so the profile now says 120 s, with that evidence.

## How the build differs from the design (in addition to `003`)

- **Cleanup runs per runner call, and literal names in case data break D1's premise.** TC-C1-1 is FLAKY because its case data fixes the tag name `"invoices"` (the binding must send it exactly, so `make.name()` can't apply). In one batch, a second test creating `"invoices"` collides when shuffled. The gate caught it correctly (passes 5/5 in order, fails shuffled), but the cause is the platform's fixed case data, not the product. **Open; options for C:** (a) `platform_rt` deletes a test's own ledger entries at teardown (cleanup per test); (b) the scaffold namespaces string case-data values under `namespace` state, except boundary-length values. Recommendation: (a). It is smaller, keeps case data exact, and matches what E's safe mode needs anyway.
- **The Alembic literal in `tp/core/sut.py` was not removed.** It belongs to the template's in-process branch-target feature and doesn't block the black-box path. It moves with the template's folder in stage D.
- **The report still advises "needs the clock/decode patches" for every unbound case** (template wording, `report/build.py:70`). Changing it changes the report golden, which the master regenerates once, in stage C, so it goes on C's list.
