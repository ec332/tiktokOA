## How the build differs from the design

1. **Image tags drop the `v`.** `ghcr.io/paperless-ngx/paperless-ngx:v3.4.2` doesn't exist, but `:3.4.2` does. `Stack.pull_matching` tries `<ref>`, then `<ref>` without a leading `v`, and fails if neither pulls (D4 still holds: never an untagged image).
2. **The Paperless profile needs `PAPERLESS_SECRET_KEY`.** The app refuses the env file's `change-me`. The fixture sets it from a generated secret (`app_secret_key`). Stage D must discover this kind of required-setting failure from the container log.
3. **Cleanup runs after each runner call (each pytest batch), not once per run.** There is no end-of-run hook, and a batch is the unit the gate repeats K times. Unique names make this safe (D1's reason still holds).
4. **Header redaction is moot for sealed records.** `platform_rt` records only `auth: true/false`, never header values. Value redaction covers bodies and logs.
5. **The secret store is per target (`data/secrets/<slug>.json`), not per run.** The stack outlives a run (the env stage reuses a healthy stack), so its generated admin password must too. A login token is forgotten at every fresh bring-up.
6. **`container` / `served` / `pytest_cases` each have two implementations.** The registered factory picks the in-process harness one when `state` is `transaction` and the black-box one otherwise (`tp/stages/env/strategies.py`). This is the A resolver's lookup plus one rule taken from the stage document's table.
