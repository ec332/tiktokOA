# SUT workspace — design (M8: repo path and branch from the web)

Agreed with the user on 2026-11-02 ("carry on with the suggested items") after the M8 design debate. M8 is not in the plan file; this debate is its source. Its goal: through the web UI only, point the platform at a repo and a branch holding a buggy price / discount% feature on Item, and get tests, located defects, suggested fixes and a retest. Happy path on this one repo.

| # | Decision | Agreed | Why |
|---|---|---|---|
| D10 | Repo input | Path typed on New run (`~/Desktop/full-stack-fastapi-template`). The platform clones it into `data/sut/<name>/` and checks out the chosen branch's HEAD; it never patches the user's checkout. Warns if the checkout has uncommitted changes (they are not in the clone) | Today a local `repo:` is patched in place (`tp/core/sut.py` checkout) |
| D11 | Branch + base | User picks the feature branch and a base branch. `git diff base...branch` defines "the feature": its changed files and lines | Drives mutation scope (gate D21) and spec focus |
| D12 | Patches | `testinfo` and `trace` always; `flags` only when seeded bugs are on | `flags.patch` edits `items.py`, which the price feature likely touches too |
| D13 | Migration probe | Expected Alembic head read from the checked-out branch, not hard-coded (`fe56fa70289e`) | The feature may add a migration |
| D14 | Mutation scope | `code_scope.mutate` becomes "the branch diff's changed lines" when a base is given; the fixed list stays the fallback | Strength measured on the feature under test |
