## 3. How the build differs from the stage document

- **`reach.health` under `--no-conventions` is `/`, not `/healthz`.** P6c's fallback, working as designed; it's the only value that differs. The done item's "same fields" holds; "same values" holds for 18 of 19.
- **r-0023 (first `--no-conventions` run) is superseded by r-0024.** r-0023's profile has no `bootstrap`: the SQLite bind mount from r-0020 survived `down -v`, so the admin already existed and no first-user creation was needed (cause inferred from the profile diff and the `Stack.start()` comment; r-0023's log wasn't kept). Fixed by removing `binds/` at every bring-up, then r-0024 was run.
- **Memos needed no exploration in the normal run** (`exploration 0`): conventions plus algorithms found everything. Exploration is exercised by `--no-conventions` (auth scheme) and on Paperless (admin env vars).
- **`setup` answers are keyed by step** (`payload.key`, e.g. `admin_env`), and an answer is fed back as a candidate on the next `advance`, so the whole discovery reruns with it. Simpler than resuming mid-step; each rerun costs one bring-up.
- **`needs_dependency` fired zero times live** on Memos (no 5xx during discovery). P8 expected `AIService_Transcribe` might; discovery never called it.
- **The `confirm_observed` answer is looked up by target slug** across resolved review items (`families_config`), because a later run is a different run from the discovery that asked.
