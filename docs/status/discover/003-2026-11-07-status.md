## 3. How the build differs from the stage document

- **A fourth layer, `algorithm`,** for values fixed code finds without a convention list or a model (compose choice, ID field, base, check op, resolver defaults). The stage document lists `convention | exploration | clarify`; without the fourth, those values would be mislabelled as conventions (inflating the convention share) or as exploration (claiming AI work that didn't happen). The `--no-conventions` compare (step 3/4) counts all four.
- **Admin env exploration brings up only the top candidate** (`shortcut:` comment in `ai.py`): each bring-up costs a minute or more. Lower-ranked candidates are tried when a target's top one fails (failure log, class "exploration miss").
- **Replay needs the repo clone** (`data/sut/<slug>`, git only, no Docker): file reads at a commit are deterministic, so they aren't recorded in the probe log.
- **`login.json: true`** is written when a login only accepts JSON; `TokenHeaderAuth` doesn't read it yet (form only). Step 2 (Memos) adds it with `bearer_login`.
- **`discover_reach` event** names the compose file, service and generated secrets.
- **A replay never writes the secret store.** Found live: the first replay (r-0018) stored the redacted `$TP_SECRET_TOKEN` placeholder as the `token` secret, which `secrets.leaks` then flagged in `probes.json`. Fixed in `step_auth`, covered by the replay test; the bad entry was removed and r-0019 replays clean.
