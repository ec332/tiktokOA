## 1. Decisions

| # | Topic | What 001 / the stage document said | Agreed | Why |
|---|---|---|---|---|
| P1 | Secured operations when the spec declares none (amends D9) | `auth.value.secured: {default, observed_open}` from a majority | **`auth.value.secured: {default, public, observed_open}`**. `default` is the majority of anonymous probes over every parameterless GET plus one item GET per resource (reads only; C's `auth_required` sweeps every method at run time). `public` holds only the sign-in and bootstrap (first-user) operations: public by evidence, not confirm items. `observed_open` holds the other anonymous 2xx reads and becomes one `confirm_observed` item, with each operation's spec description quoted as evidence. **Consumer:** `families_config` passes the map in `$TP_FAMILIES`; `secured()` becomes *the spec declares security, else the profile default, unless the operation is `public` or `observed_open`*. On a default-secured operation an anonymous 2xx is a product failure; on `observed_open` it stays `SPEC_MISMATCH` until the answer flips it to secured or public. platform_rt 0.7.0 → 0.8.0 | 001's map had no reader: `secured()` reads only the spec, so on Memos every anonymous 2xx would have stayed `SPEC_MISMATCH` |
| P2 | ID-field detection (amends D12) | Try each scalar field of the create response as the read operation's path parameter | **Try each scalar value verbatim, then, for a string containing `/`, its last segment.** Tie-break: verbatim over suffix, then the field whose name equals the path parameter, then response order. Every field that worked is recorded as evidence. `id_style` is the JSON type of the winner | Memos: `name: "memos/abc"` while the path is `/api/memos/{memo}`; verbatim gives `/api/memos/memos/abc` (spike, §2). `delete_path` already takes the last segment |
| P3 | Paging under `--no-conventions` (amends D12) | Candidate names from `paging_param` conventions | **Candidates are the list operation's own query parameters from the spec**; `paging_param` conventions only rank them. Styles are C's two: `page` (integer page + size) and `token` (size + a string token echoed from the response). Limit/offset or anything else → `paging: null` with a reason (C's paging family then doesn't run); no third style. Verified: create two items, page of size 1, follow `next`/`next…Token`; page 2 must return a different item | Without conventions the names would be guessed; the spec already lists them |
| P4 | Round-trip exclusions (replaces D10) | `data.roundtrip_exclude`; other differences → `confirm_observed` | **Dropped. D produces nothing for round trips.** | C's `read_back` already skips `writeOnly`/`format: password` fields and `*`-masked values at run time, and fails on any other difference (`families.py` `_write_only`, `_masked`, `read_back`) |
| P5 | Endpoint confirmation (amends D8) | Per-operation check against a garbage path's 404 fingerprint; unconfirmed operations dropped | **No per-operation dropping. A spec-level sanity check:** the anonymous reads already probed for P1, plus the data step's create / read / delete with real IDs; the spec is accepted when most of them differ from the garbage-path fingerprint, else discovery tries the next spec candidate. Step order stays reach → spec → auth → credentials → data, with the check after data | grpc-gateway's real-route-unknown-ID 404 and its no-route 404 share status, content type and JSON keys; only `message` differs (spike). D13 makes the spec match the image by construction, and C's families report a route that is really missing |
| P6a | Paperless commit (amends D14) | Latest release tag by default | Acceptance runs **`tp target add https://github.com/paperless-ngx/paperless-ngx@v3.4.2`**, the fixture's commit | The latest tag may have moved past the fixture's |
| P6b | Auth scheme choice (amends D14) | Not stated | **Fixed preference in `config/discovery.yaml`: a login that returns a token, then basic, then cookie**, first verified wins. The header prefix is a candidate list: `Bearer` (RFC 6750), `Token` (DRF `TokenAuthentication` docs) | Paperless declares basic, cookie and token; basic would verify first and give a profile unlike the fixture's `token_header`. The `Token` prefix is only in the schema's prose |
| P6c | `reach.health`, `auth.check` (amends D14) | Not stated | **health** = the served spec path when the spec is served, else the first `health_path` that answers 2xx, else `/`. **check** = the first secured parameterless GET in spec order. The comparator accepts any secured parameterless GET for `check` | Both are choices in the fixture, not facts |
| P6d | `spec.base` | Not stated | **The longest common segment prefix of the spec's paths** (Paperless `/api`, Memos `/api`) | `TP_API_BASE` silently falls back to the template's `/api/v1` when unset |
| P6e | Admin env vars, generated secrets (amends D14, D17 step 1) | Paperless "via conventions"; secrets for placeholder values of secret-like vars | **`PAPERLESS_ADMIN_USER`/`_PASSWORD` are found by exploration** (`docs/configuration.md`), `layer: exploration`; no convention entry, since no framework documents that name (Django's is `DJANGO_SUPERUSER_*`). The comparator compares values, not layers; D17 step 1 becomes "Paperless via conventions + exploration". A generated secret replaces a value only when it is a placeholder (list in config) **and** only one service reads the variable | An `admin_env_pattern` entry for this name would be justified by the target alone (rejected by the stage's own rule). One reader only: a generated value must not desync an app and its database |
| P6f | Image tags | `retag` rewrites `:latest`/untagged only | **The registry check tries the ref with and without a leading `v`; a README or compose image with a floating tag (`latest`, `stable`, `main`, …, list in config) is retagged to the release tag only when that manifest exists** | `retag` treats `:stable` as pinned; Memos's README image is `neosmemo/memos:stable`, its release tag `26.11.0` |
| P7 | Memos auth, short-lived tokens (amends the `bearer_login` shape) | `bearer_login` with a sign-in op | **`bearer_login` = sign-in op + `token_field`, plus expiry.** The expiry comes from a JWT `exp` (RFC 7519) or a `…ExpireTime`/`expires_in` field of the login response; platform_rt logs the principal in again when less than 60 s remain. Re-login is proactive, never on a 401, so a 401 is still evidence | Memos's sign-in token lives 900 s (spike), shorter than a run. Re-login on 401 would hide auth defects; a long-lived personal access token would add a target-shaped second step |
| P8 | `needs_dependency` (confirms D11) | 5xx plus a container log naming a var the code reads but nothing supplies | **Agreed, made language-free:** "the code reads it" = the name appears as a string literal in the repo's source, and the variable is unset in the container. ## 2. Memos spike (read-only, no code, $0)

`neosmemo/memos:26.11.0` (the latest release, 2026-11-01; Docker Hub tags `26.11.0`, `26.11`, `stable`, `canary`) on host port 15230; spec `proto/gen/openapi.yaml` at tag `26.11.0` (gnostic `protoc-gen-openapi`, OpenAPI 3.0.3, 93 operations, no `security` anywhere). Container removed afterwards; image kept for the live run.

| Probe | Result |
|---|---|
| `GET /healthz` | 200 `text/plain` "Service ready." |
| `GET /api/instance/profile` (anonymous) | 200, `needsSetup: true`, `accessMode: INSTANCE_ACCESS_MODE_PRIVATE` |
| `POST /api/users` (anonymous, first) | 200 `{"name":"users/tpadmin", "role":"ADMIN", "password":""}` |
| `POST /api/users` (anonymous, second) | 200, role `USER` (sign-up open by default) |
| `POST /api/auth/signin {passwordCredentials}` | 200 `{user, accessToken, accessTokenExpireTime}`; JWT `exp − iat` = 900 s; `Authorization: Bearer` works on `GET /api/auth/me` |
| `POST /api/memos` ×3 (`content`, `visibility`, `state` required) | `name: memos/<22-char id>` |
| `GET /api/memos/<suffix>` | 200 (verbatim `name` would give `/api/memos/memos/<id>`) |
| `GET /api/memos?pageSize=1` → `nextPageToken`, then `&pageToken=` | page 2 is a different memo, with its own `nextPageToken` |
| Authed `GET /api/memos/tp-no-such` vs `GET /api/nope/xyz` | both 404 `application/json` `{code: 5, message, details}`; only `message` differs |
| Anonymous sweep: 27 GETs (parameterless, plus `{memo}`, `{user}` filled) | 25 × 401 `{code:16, "authentication required"}`, 2 × 200: `/api/identity-providers`, `/api/instance/profile` |

Spec facts: every path starts with `/api` (not `/api/v1`); custom-method paths (`/api/users:batchGet`, `/api/memos/{memo}/shares`), a `*` template (`/api/instance/{instance}/*`); operation descriptions state access in prose ("Public.", "Requires authentication.", "The first user of an instance becomes an admin."); `User.password` is `writeOnly` and read back as `""`.

**Consequences:** `tests/fixtures/targets/memos/profile.yaml` (C's contract-test fixture) is wrong on `spec.base` (`/api/v1` → `/api`) and `reach` (`scripts/Dockerfile` → the release image); D corrects it when it touches the fixture. C's path handling must tolerate the `{instance}/*` template (check in build step 2).
