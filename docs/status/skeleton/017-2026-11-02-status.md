## 2. Review of the real runs against the brief

Read through the API: `GET /runs/{53..56}`, every output artifact of r-0056, `/reviews` items for executions 593/594/599, and the generated tests in `data/runs/gate-exec-596/tests/`.

### G1. The feature's own calculation is never asserted (brief 2 and 3) — highest value
The causes, in order:
1. **Spec: orphan questions overwrite C-1.** The questions on rounding, null price, null discount on update and negative price on update were all attached to `C-1` (review items 178–181). Each answer replaced C-1's resolution and expected status. The last one won: C-1 = "Responses show the discounted price", `status_code: 422`, `resolution: "422 as on create"`.
2. **Spec: duplicate questions.** Null discount and negative price on update were asked twice: once on O-5/O-4 (defect) and once on C-1 (ambiguity).
3. **Spec: answers that change a value don't become a criterion.** "rounding: half up" sits only in `decisions`. No criterion's Then mentions it, so cases never saw it. The spec's own finding noted that the code uses half-to-even.
4. **Cases: the traceability check dropped the positive test.** `attention`: "C-1: dropped a drafted case: expected '2xx' is not traceable to C-1 (spec allows ['422','4xx'])". C-1's only case is a 101-discount → 422 test.
5. **Cases: status-only oracles.** 41 of 45 expectations are `literal` status codes. TC-O1-1 ("final_price 7.50" in O-1's Then) asserts only `200` (`test_tc_o1_1.py:18`). Only TC-O8-1 uses `observe` + `expect.equals`, with the `newest_first` calculator. No case used `percent_off`. `round`/`half`/`percent_off` appear 0 times in the cases.

Result: C-1 and O-1 are WEAK with 0 kills, listed as uncovered, and a rounding discrepancy the user answered is never tested.
