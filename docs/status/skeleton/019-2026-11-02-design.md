# Skeleton — design (M8 iteration: live activity panel on the run page)

Asked for by the user on 2026-11-02 ("a collapsible window… what exactly is being done while the stages are being called… on the right side").

| # | Item | Before | Agreed | Why |
|---|---|---|---|---|
| A1 | Where | Each step showed only its latest event line | A right-hand **Activity** panel on the run page, collapsible to a slim tab; open/closed is remembered per browser (localStorage, wrapped in try/catch). Below 900px it stacks under the steps. | Watch the stages work without losing the steps view. |
| A2 | Content | — | Every event of the run, oldest first: time (GMT+8, with seconds), stage tag, one plain sentence (`say()` extended to stage start/finish, waits, AI calls with model and cost, run end). Unknown kinds show as `kind` + compact payload. Click a line to see its raw payload. | Plain language first, raw data one click away. |
| A3 | While a stage runs | — | A pinned "Now: <stage> — <what it does> · elapsed" line at the top, with a one-line description of each stage. | Long phases still show something alive. |
| A4 | Scrolling | — | Follows new events while scrolled to the bottom; stops following when the user scrolls up. | Standard log behaviour. |
| A5 | Data | — | Same `events/list` query the page already refreshes from the SSE stream. No new endpoint. | Nothing new to keep in sync. |
| A6 | Gate progress (gate/008) | Silent for minutes between phase ends | See gate/008. | The longest stage had the fewest events. |
