# Skeleton — design (001, 2026-10-31)

You asked to go straight to building the skeleton and argue design at later stages. So these
decisions were **not debated**. Each one is either the plan as written, or the smallest choice
that fills a gap the plan leaves open. They are open to challenge at the next stage boundary.

| # | Topic | Plan says | Built | Why |
|---|---|---|---|---|
| D1 | Artifact id | file under `data/artifacts/<sha256>` | id = sha256 of canonical `{manifest minus id/created_at, body}` | Hashing the body alone would merge two artifacts with the same body but different parents/labels/stage version, and lineage would be lost. With this rule, a `recorded` replay is a different artifact from the `real` one. |
| D2 | "Superseded" | not defined | head of a type in a run = output of the latest succeeded execution; stale = a succeeded execution consumed an artifact that is no longer a head (applied transitively) | One query, no new table. A re-run with identical output marks nothing stale. |
| D3 | Resume after review | "runner resumes it" | `run()` is called again on the same execution, with resolved items visible through `ctx.review.items()` | No stage state to save. Stages must be idempotent, which content addressing + LLM replay give us anyway. |
| D4 | Unattended mode | spec/cases mention defaults/`unsigned` | `--unattended` auto-resolves `signoff`/`question` as `defer` (logged as `by: unattended`); other kinds stop the run | Lets `tp run --stub` finish headless while still carrying the `unsigned` label. |
| D5 | `produces` | `list[str]` | `dict[str, int]` (type → schema version), mirrors `consumes` | The runner needs the version to write the manifest, and the contract test needs it to check consumers. |
| D6 | LLM modes | live / record / replay | live and record both call and record; replay reads only, and a miss raises `ReplayMiss` (never falls back to live) | Part 5 says every call is recorded. No real provider until M2; stub runs use a deterministic echo provider so record/replay is exercised. |
| D7 | Concurrency | single worker thread | one worker thread per process + SQLite WAL | The API and the CLI are separate processes. WAL makes concurrent use safe. There is no cross-process lock: two processes driving the *same* run is unguarded. |
| D8 | Canonical JSON | normalise floats/newlines | `\r\n`/`\r` → `\n`, `-0.0` → `0.0`, shortest round-trip float repr, NaN/inf and non-string keys rejected | Deterministic across processes (tested in a subprocess). |
| D9 | uv workspace | workspace | a single package | A workspace pays off only once `platform_rt` exists (M3). |
| D10 | Fixture uploads | "upload fixture" | `POST /artifacts` / `--input type=file.json`, labelled `pre-generated` | Hand-written inputs stay visibly not real downstream. |
| D11 | Skeleton test location | each stage has `tests/` | core tests live in top-level `tests/`, owned by skeleton in `docs/folders.yaml` | `tp/core` has no stage folder shape. |
