# Spec — design (M8 iteration: default clarification rules say "settle", not "check")

Agreed with the user on 2026-11-02 (see skeleton/016 for the UI side).

| # | Item | Before | Agreed | Why |
|---|---|---|---|---|
| R1 | `prompts/rules.md`, the 6 defaults | "check the minimum, the maximum, and just outside both", "check each kind of caller"… | "settle its minimum and maximum, and what happens just outside them", "settle what each kind of caller may do"… | "Check" read as test design, which belongs to the cases templates. Spec's job is to make the expected behaviour known. "Ask" was rejected: it conflicts with the investigator's "ask only when at least two answers are plausible" and would inflate the questions. |
| R2 | `prompts/investigator.md`, rules header | "Rules for test design to apply while reviewing:" | "What the requirements must settle. Settle each point from the requirements text, then the code (as an observed criterion), and ask a question only when both leave it open:" | Same reason. It names the order (text → code → question) that the clarify step already follows. |

**Open:** this is a prompt change. Per the no-LLM-output-tests rule it isn't covered by a golden test; the next real run must show the question count and requirements are no worse than r-0056 (7 defect causes, one "Other…" answer).
