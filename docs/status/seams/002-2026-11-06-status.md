## How the build differs from the stage document / design

1. **The shim's direction.** The design's reverse shim exists (`profile.legacy`), but `ctx.env` is **not** a shim over the strategies: the env SERVICE stays the template's implementation, and the strategies are facades over it. `ctx.env` is still on the context but nothing reads it; it is removed with the shim.
2. **Interfaces carry `variant`.** Every Reach/Spec/State/Data/Check method takes `variant="reference"`, because the template's planted bugs and fixes are whole stacks. Black-box targets only ever pass `reference`. Reach also gained `ensure`, `guard`, `logs` and `image`; Mutation gained `flags`, `scope`, `harness_files` and `seeded`. `Safety.allow` takes `(method, path, target_id)` for now (stage E settles the Operation type). `stage document A-seams.md` interfaces block updated to match.
3. **`rank()` regression baseline.** r-0002's stored order is older than today's `rank()` (it predates `b973dc1`, feature-first priority), so the fixture freezes **today's** `rank()` output on r-0002's inputs.
4. **Priority config is smaller than the plan's example.** Only the terms `rank()` uses today; the discovered-target terms come with stage C, the PR score with F (lean scope).
5. **Folder rule.** `docs/folders.yaml` gains milestone `I2` (current) and owner `seams` for `targets/`, `config/` and the new core modules. The iteration 1 per-file entries for `sut/patches/*` were dropped: `targets/` owns the whole folder. Cross-cutting A5 edits are to be committed under each owning stage's tag.
