# Generic checks + triage — status: `read_back` false defect on "unset" enum values (maintenance)

Fix of 2026-11-07, requested from stage D's close-out (`discover/007` Q8). Done before F, which turns defects into issue drafts with no click.

## Defect

On Memos, every run reported `PRODUCT_DEFECT` `G:read_back:POST /api/memos` (r-0025, r-0031):

```
GET /api/memos/<id>: declared fields did not round-trip (sent, read):
  {'visibility': ['VISIBILITY_UNSPECIFIED', 'PRIVATE'], 'state': ['STATE_UNSPECIFIED', 'NORMAL']}
```

Cause: `families._valid` sent an enum's first value. In proto3 / Google AIP-126 APIs the first value is the zero value `*_UNSPECIFIED`, which means "unset", so the server stores its default. The check was right about what it saw; the body was wrong to send "unset".

## Fix

`platform_rt/platform_rt/families.py` `_valid`: an enum gets its first value that isn't an AIP-126 "unset" name (`(^|_)UNSPECIFIED$`, https://google.aip.dev/126); if every value is one, the first is kept. `read_back` itself is unchanged, so it still fails on any real round-trip difference. platform_rt 0.8.0 → **0.8.1**; the template runner image rebuilt (`tp generate image`, `platform-rt 0.8.1`).
