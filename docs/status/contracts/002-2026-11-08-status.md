## How the build differs from the brief (the brief is updated to match)

1. **C2 extends an existing module.** `tp/core/labels.py` already held iteration 1's provenance labels for artifacts (`real`, `simulated`, `pre-generated`, `recorded`, `unsigned`). So `basis` uses those words: `pre-generated` with a hyphen, not `pre_generated`. The file stays `skeleton`'s, and the registry line that gave it to `contracts` is gone.
2. **C3: a failed assert in a collector raises `expect.ExpectationFailed`, not `AssertionError`.** `origin.classify` classes anything else raised inside platform_rt as PLATFORM. A test pins this for P5 and P7.
3. **C6: `spec_base.base(spec, fallback)` takes the fallback as an argument.** That way `spec_base` never imports `discovery`, and there is no import cycle.
4. **C7 is refined.** Under a recorded fault:
   - an ENV origin also counts as product side, since a timeout to the SUT under an injected delay is the SUT failing to absorb the fault;
   - `SUSPECT_ENV` batches stay ENV.

   This changed P6's brief: `dependency_failure_handled` passes a 502, 503 or 504 (the graceful answer) and fails on a 500 or a hang. The clean fixture's invite answers 502 when the mail server refuses, and it must pass.
5. **Test files.** The contract tests live next to the code they pin (001 W6). The runtime's is named `test_rt_contracts.py`: a second `test_contracts.py` basename broke the full run's imports.
6. **The base image.** `docker build` found `python:3.14-slim` without an explicit pull. No `python` tag shows in `docker images`; 001 W4 stands.
