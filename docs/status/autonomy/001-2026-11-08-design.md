No new stage. The debate proposed a new `fix` stage. Reading the code showed triage already does this for every `real` defect, and the UI's "Try suggested fix" proves it with a retest | The model work already exists and is checked by fixed code. | F2 | Seeded defects on the fork | "The template fork, which has known seeded defects" | The fork `ec332/full-stack-fastapi-template` holds the bugs only as `BUG_*` flags, added at build time by `flags.patch`. **One branch on the fork writes 2 seeded bugs as plain code**: `BUG_OWNERSHIP_UPDATE` (a user can change another user's item) and `BUG_TITLE_MAX` (titles of 255 characters are refused). The platform's target is a local clone of the fork whose `origin` is the fork. Pushing that branch is the `tp watch` trigger | A real PR has to remove real code. | F3 | Pipeline shape | "After the report, for each defect" | `… report → retest → deliver`. **retest** with no `defect` option and `auto` set (every focused run) retests every `real` PRODUCT_DEFECT whose suggestion applies, as `fixed:<fix_patch>`, K=5, same hashes. **deliver** (new stage, no LLM) scores each defect and writes a PR or an issue draft | Follows the existing stage contract. | F5 | Q2: where issue drafts go | File in the run, or `gh issue create` | **A file only**: a `delivery` artifact holding each issue's markdown, also written to `data/runs/<run>/issues/<defect>.md`. | F6 | PR score | `severity × evidence + fix`, threshold 3, `data_loss` in severity | **`score = severity × evidence`**, threshold 3. FIXED_CONFIRMED is a **hard rule**, not a term (a PR needs it anyway, so the term was always 1). **`data_loss` dropped** (nothing detects it). Severity from a fixed rule on the failed status assertion: actual ≥ 500 → `server_error` 3; expected 401/403, got 2xx → `permission_bypass` 3; expected another 4xx, got 2xx → `validation_gap` 1; otherwise `wrong_value` 2. Hard rules: class PRODUCT_DEFECT only; `SPEC_MISMATCH` and external reach → issue; only a fork we own (`gh repo view`: `isFork` and write permission); at most 3 PRs per repo per day. Every result is `{score, parts, rules}` | Same no-model scoring as the case score (`tp/core/priority.py`). A term that never varies just adds noise |
